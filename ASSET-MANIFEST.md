# ETERIOMN visual asset register

`assets/asset-manifest.json` is the canonical structured inventory for every local image and webfont. Keep its source, creator, license, attribution, intended use, acquisition-date uncertainty, replacement status, temporary status, alt text, dimensions, and aspect ratio accurate whenever an asset is added, removed, or repurposed. An unknown source is recorded as unknown—not inferred from the filename or visual style.

## Identity rule

**ETERIOMN itself is the complete logo.** The navigation and footer render editable HTML text, `ETERIOMN`, using the shared Space Grotesk wordmark treatment. Do not add a pictorial emblem, monogram, standalone symbol, or “E.” motif. `images/brand/eteriomn-wordmark.svg` is a text-only favicon/web-app asset. `images/brand/eteriomn-social-card.svg` is the editable vector companion to the separately maintained 1200 × 630 PNG. The build does not convert between them, so update both and inspect their alignment whenever the sharing card changes. The full wordmark is necessarily small at browser-tab size; do not replace it with a different mark.

## Local type system

The site self-hosts Space Grotesk for the display face and wordmark, Inter for body/interface text, and IBM Plex Mono for technical labels. WOFF2 files and the complete SIL Open Font License 1.1 notices are stored in `assets/fonts/`. No external font request or mandatory font package is used. The Latin Inter subset covers Albanian `ë` and `ç`; Latin Extended subsets are available for additional glyphs.

## Replacement workflow

1. Use an original asset created for this project or an appropriately licensed source whose terms can be recorded. Do not hotlink unknown media or use a reference image without verified rights.
2. Add/update the structured entry in `assets/asset-manifest.json`. Record the actual source URL or state that it is unknown, the creator, license, attribution, intended routes, acquisition date or explicit uncertainty, replacement/temporary state, accurate alt treatment, dimensions, and aspect ratio.
3. Update centralized paths in `src/data/visuals.js`, `src/data/projects.js`, or `src/data/collaboration.js`, and update page-specific image dimensions and alt text in the same change. Decorative images may use `alt=""` when nearby content already communicates their purpose.
4. If the hero changes, update the home-page alt text and both social-card SVG/PNG companions. Preserve the editable ETERIOMN wordmark and inspect visual alignment; image conversion is not part of the npm build.
5. For service illustrations, edit `src/data/service-illustrations.js`, preserve one distinct diagram and description for each confirmed route, then rebuild the atlas with `npm run build`.
6. Run `npm run validate` and `npm test`; inspect SVG/XML and affected routes. Browser, viewport, screen-reader, and formal accessibility checks require separate manual testing.

Never reuse one image across unrelated service pages merely to fill space. Use video only when it adds information or meaning, and supply a static fallback, accessible controls/captions where applicable, and reduced-motion behavior.
